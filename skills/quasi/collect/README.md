# 收录材料

如果你是被直接派到这里的，先读本技能根目录的 `SKILL.md`。

## 先判断材料类型

| 材料 | 下一步 |
|---|---|
| 期刊论文、工作论文、会议论文、学位论文 | 读 `collect/paper/README.md` |
| 书（专著、文集）、书的章节 | 读 `collect/book/README.md` |
| 讲座、访谈、对谈的录音录像 | 读 `collect/talk/README.md` |
| 要读的网页文章：博客、新闻、评论 | 读 `collect/webpage/README.md` |
| 要当原件存档的东西：帖子、专利、手册、图片、视频 | 读 `collect/archive/README.md` |
| 把文库里的论文或书翻成译本 | 读 `collect/translation/README.md` |
| 一位作者的代表作和作者页 | 读 `collect/author/README.md` |

类型拿不准时（比如一个链接可能是论文，也可能是普通网页），先查一下再定；查过还拿不准，就问用户。同一个链接，用户想读文章就按网页收，想保存原件和出处就按档案收。

一次要收好几件材料时：

- 件数少，就逐件处理；
- 件数多，每件派一个工人从头跑到尾。派活消息里写明对应材料的入口文件（绝对路径）和材料线索。

## 所有材料共用的规则

**写作一律派写手。** 写手要换成中文写得最好的模型，也需要干净的上下文。交给它的只有写作说明的绝对路径、输入文件和书目信息，消息开头和末尾按 `connectors/rex.md` 加上工人身份和交付方式；写手不读这棵目录树。

**只验产物，不验汇报。** 文件在不在由 `quasi status` 判断，合不合格由 `quasi audit` 判断。工人的回复只用来知道有什么需要用户决定，或者为什么做不下去。

1. 同一个输出路径，同一时间只派一个工人。
2. 工人结束后看磁盘、跑 audit，不信汇报。
3. 返修时，把原写作说明、audit 诊断和现有文件一起交给写手，保留用户自己写的内容。
4. 工人崩了或结果不明，先看磁盘再决定，不盲目重派。

**audit 的处理。** `quasi audit --path 页面` 会自动完成确定性修正，然后报告剩下的诊断（退出码 1 也可能是正常的诊断结果）。剩下的分两种处理：

- 字段值、标题层级、结构形状这类机械问题，而且现有内容就能决定怎么改的，你直接改，再跑一次 audit；
- 需要回到原文重新判断或重写的，交回写手返修。返修一次仍不合格，停下来告诉用户还差什么。

**完成后**，向用户报告产物路径和遗留问题。如果装了 `marple-cli`，就用 `marple-cli open 页面路径` 打开；打不开就算了。
