# 下载论文

目标是把这篇论文的完整全文，以 PDF 或 UTF-8 文本的形式接收进 `sources/`。整个过程只接收一次。

## 下载

```sh
quasi download paper fetch --slug SLUG --doi DOI --title 题名 --author 作者姓 --json
```

如果查身份时拿到了直接的 PDF 链接，用 `--url` 传进去，可以重复多次。CLI 自带一整套来源级联（开放获取、出版社、EZProxy、Kagi 找回等），默认前台预算 480 秒，所以调用时给命令留至少 540 秒的超时。

按返回的 `status` 处理：

- **`ok`**：拿到了候选，照下面的方法核对后接收。
- **`identity_uncertain`**：不是下载失败。CLI 已经拿到候选，只是机械检查不足以确认身份。逐个读候选的 `inspect.front_text`，必要时直接看临时文件的首页、末页和一小段正文，结合题名、作者、期刊、年份、主题和文件里嵌的 DOI 判断。排版拆字、旧文本层、轻微 OCR 错字都不足以否定一个候选；嵌入了不同的 DOI，或者作者、作品明显不同，才是排除的证据。
- **`budget_exhausted`**：预算用完了。先按上一条的方法核对已经拿到的完整候选；一个都不能接收的话就停下，告诉用户可以稍后重试。同一次处理里不要再启动第二轮完整下载。
- **`failed`**：所有来源都失败了。如果还有可靠的新线索（新的链接、别的题名写法），可以把它们作为新输入再调用一次 fetch。不要在外面自己实现另一套下载器。

遇到 4xx、登录页或人机验证时，可以对同一个网址跑一次只读诊断：`quasi download paper diagnose --url 网址 --json`。它只说明这一个网址发生了什么，比如 `mode:"direct"` 时只能说明直连被拦，不能说明 EZProxy 也被拦。

## 核对与接收

接收之前，必须确认候选是这篇论文的**完整全文**：题名、作者、版本都要对得上。摘要页、落地页、预览、导航壳、登录页一律不收。

- HTML 候选只会作为临时 `.html` 文件返回，不会自动变成正文。只有确认它是完整全文时，才能在同一个临时目录里用现成的工具转成严格 UTF-8 的 `.txt`，核对后再接收。
- 确认无误后，只接收一个：

  ```sh
  quasi download accept --path 临时文件路径 --slug SLUG --kind paper --json
  ```

  读返回的 `published` 路径和 SHA-256，确认接收成功。
- 最后删掉这次 fetch 返回的、没有被接收的临时文件。

一个候选都不能接收时，把临时文件全部清掉，告诉用户试过哪些来源、各自是什么结果。凭证、cookie、签名链接不要写进给用户的报告。
