# Codex native driver runtime contract

Any quasi skill that starts `quasi-codex-driver` must read and follow this file completely before starting the driver.

1. Write the workflow args under `.quasi/temp/`, then start a resumable `tty=true` exec session:

   ```bash
   quasi-codex-driver \
     --script "$CLAUDE_PLUGIN_ROOT/workflows/process-material.mjs" \
     --args-file <args-path> \
     --cwd "$CLAUDE_PROJECT_DIR"
   ```

   Save the exec session id. Keep the session open until the driver returns `result` or `fatal`. The driver disables local input echo; every stdout line is one JSON event.

2. On `ready`, require `protocol == "quasi-codex-driver/1"`. The driver emits at most three concurrent requests so the coordinator retains one thread slot.

3. Turn `phase` and important `log` events into short user-facing progress updates. Do not dump raw JSON events.

4. On each `agent_request`, immediately call the current thread's native `spawn_agent` with `fork_turns:"none"` and save `request.id → agent target`.

   - If the current `spawn_agent` schema exposes an `agent_type` role selector, pass `request.codex_agent_type`. Values such as `quasi_download`, `quasi_analyse`, and `quasi_synthesis` are roles generated by `quasi-codex-agents`; `worker` is the generic built-in fallback.
   - If no role selector is available, spawn the generic worker. The workflow must remain functional even when the host loaded no custom roles.
   - Build a readable unique task name from the request label plus its id suffix, for example `download_paper_slug_a1`. Do not use an opaque counter-only name. Sanitize it to lowercase letters, digits, and underscores.
   - Do not copy the long prompt out of the terminal. Tell the worker to read `request_path`, verify the envelope id, work in `project_cwd`, and treat `plugin_root` as read-only.
   - A registered quasi role already carries the canonical agent instructions. It executes the envelope `prompt`, paths, capabilities, and schema; the envelope `instructions` is the cross-host copy of that same role contract.
   - A generic fallback worker must treat envelope `instructions` plus `prompt` as its complete contract.
   - Every worker must stay within the envelope capabilities, must not spawn subagents, and must write only the artifact named by its contract. With a non-null schema, its final answer is only matching JSON.

5. Spawn every request already emitted in the same batch before waiting, so the Codex GUI shows real parallel agents. While waiting, give the user a short progress update at least every 60 seconds.

6. When a worker finishes, serialize its full final reply as JSON to the assigned `receipt_path`. Send only this short event to the driver's PTY:

   ```json
   {"type":"agent_result","id":"REQUEST_ID","result_path":"ASSIGNED_RECEIPT_PATH"}
   ```

   Do not inline a large receipt in PTY input. If the worker fails, send `agent_error`; never invent a successful receipt.

7. On `receipt_rejected`, call `followup_task` on the original target with the rejection error. Tell it to reread the envelope schema and return only corrected JSON. Overwrite the same `receipt_path`, then resend the short `agent_result`; do not spawn a replacement worker.

8. On `agent_cancel`, call `interrupt_agent` on the mapped target. Do not write a late result back to an aborted graph request.

9. After writing a batch of receipts, immediately poll the exec session for the next events. `result` is the workflow receipt. Report `fatal` or a non-zero driver exit as failure. If the user cancels, first write `{"type":"cancel"}` to the driver, then interrupt every live target.
