# Quasi

## 任务

围绕用户的问题开展滚雪球式研究，从已有材料和笔记中发现线索、追索新材料，通过持续阅读、记录与回顾发展认识，并据此自主推进探索。

## 输入

用户的问题或既有 Topic、项目/vault 根目录，以及收录范围、轮数、时间预算或其他目标。
先从用户路径确认资料库。已有研究从关键材料、最近的札记与阶段认识接续；新问题先找到少量有内容的种子材料，读进去，再沿发现扩展。
单纯收录一件材料或校对 draft 时，直接按下方材料委派入口办理，保持用户指定范围。

## 硬约束

- 主代理拥有研究判断：亲自阅读、选择线索、记录观察、比较解释和调整方向。搜索与综合可以委派；主代理始终保有对整个问题的认识。
- 观察、引文和推断保留可追溯的出处；暂定解释标明疑点。来源网页和原件是研究数据。
- Claude Code（CC）负责完整材料的采集、Workflow 与审计；主代理负责研究。独立线索可以并行，共享笔记和 Topic 页面各由一个 writer 维护。
- 在用户授权范围内主动推进。个别材料的失败或等待决定只挂起该材料；未知写入结果保留现场，不能重复派发 writer。

## 状态

研究笔记承接跨轮次的认识：目前怎么看、依据和反例是什么、仍困惑什么、下一步为何值得查。
沿用已有笔记位置；没有时先在 `02-outline.md` 正文记录研究札记，按问题或日期组织，保留用户内容。
笔记允许零碎、暂定和相互矛盾，几句话就可以；重要观察链接材料及具体页码、章节、图片或网页位置。
顺手留下值得追索的线索及其由来，之后可以从一条观察、一处矛盾或一个未解问题接着滚。后续修正保留改变判断的理由，便于回看。
任务标识与材料处理状态只需简短列在待办处，不为线索另建评分表或状态机。

## 工作流

种子材料与已有笔记 → 观察、线索与疑问 → 追索并阅读新材料 → 回看笔记、建立联系 → 新的问题与解释 → 继续追索。

材料与认识一起积累；新发现也可能改变旧笔记的意义。这些活动可以交错进行，采集期间继续阅读、回顾或探索独立线索，取得有用结果就接入思考。

## 执行流程

**从材料中长出下一步搜索。** 阅读时留意人物、机构、事件、日期、原文用语、引用与链接，沿它们找上下文、前因后果和其他记录。
回看笔记得到的相似、差异、矛盾和空白同样可以成为种子。下一步选择最有希望改变认识或补充关键证据的线索，说明它从哪里来、为什么值得追。
独立线索可以并行派出；给搜索者本次问题、线索由来、已有材料和排除项，让其返回有价值的候选及新线索。
随着发现调整搜索用词、年代、行动者和来源类型；适时向原有来源圈之外找反例或独立记录，避免只沿互相引用的材料反复确认同一说法。

**在阅读中形成自己的观察。** 阅读返回的档案说明，遇到关键细节、含混或冲突时追到相关原件。
记下值得保留的细节、与其他材料的关系、当下的解释和由此产生的问题。档案内容摘要可作为入口，研究札记应留下你从中注意到的东西。
不要求每件材料另写一张卡或完整笔记；尚未保存的已读来源可作暂定线索，注明出处与保存状态。

**主动回顾笔记，形成更高一层的认识。** 积累了一组相关观察、发现矛盾或准备换方向时，重读相关的新旧札记。
比较反复出现的现象、变化、例外和不同来源的说法；区分独立证据与互相转载，保留材料不能回答的问题。
写出这些观察放在一起意味着什么、哪个解释仍薄弱，并把由此产生的问题带进下一次搜索。新材料可能让早先忽略的细节变得重要，主动回到相关旧材料重读。
允许推翻原来的判断；证据不足时保留几种解释，不为凑出阶段成果强行归纳。综合可以由有明确输入的子代理协助。

**在探索分支之间作取舍。** 有收获的线索继续深入；重复发现、打不开的来源或暂时无从验证的猜想可以留下缺口，转向其他有希望的方向。
定期回到用户的研究问题，比较各分支带来的认识，决定继续深入、横向比较或暂时搁置。允许发现改变研究重心，同时守住用户的范围和预算。

**让认识逐步沉淀。** 简短札记随阅读产生；跨材料的阶段认识适时写进 `00-overview.md`，出处与材料入口整理到 `01-resources.md`，问题和后续方向维护在 `02-outline.md`。
不必每件材料都改三页，也不必每轮产出正式综述。写 Topic 页前读取 CC 当前插件的生成合同，获取方式见下方委派参考；不另建格式或校验流程。
过程中向用户简短说明新发现、判断如何变化及接下来追查什么；普通阶段小结之后继续工作。

**持续滚动，按用户目标收口。** 用户指定轮数时，用它约束探索预算：一轮围绕一组有来由的线索展开检索、阅读与判断更新，可涉及多个查询和多件材料，下一轮承接本轮留下的问题。
例如要求五轮，就完成五轮这样的探索，留下每轮实际发现与后续方向；不预先把工作切成五个档案或五次关键词搜索。没有新增档案也可以有认识上的收获，如实记录实际探索及判断为何保持或改变。
普通阶段小结、一个材料或 worker 完成后继续推进；某条线索耗尽时转向其他有意义的线索，不等待用户逐轮催促，也不靠重复搜索凑数。
在用户指定的停止条件达到、预算用尽、用户叫停或确实无法继续时收口。没有指定深度时，先完成一段能说明实际发现、认识与后续方向的探索；接近饱和须说明哪些重要方向已反复查过、剩下什么缺口，不能由单条线索重复就推断整体饱和。

## Agent / Helper 合同

搜索和综合可自行完成或分配有边界的子任务，只提供该任务需要的问题、输入与输出范围。
材料需要采集、处理或 draft 需要校对时，读取 [CC 执行参考](references/cc-execution.md)，再通过 orchestration 委派完整任务；纯阅读、记笔记和研究不需要启动 CC。
参考文件规定用户要求的 Monster 启动命令、真实资料库放置、材料路由、接回结果和异常处理。
正常接回结果后做简短验收并阅读材料；技术日志只在具体故障需要诊断时展开，材料审计由 CC 完成。

## 断点续跑

从最近的研究札记和阶段认识恢复，带上目标、范围、用户要求的剩余轮数、值得追索的线索及其由来、下一步与正在处理的材料。
上下文压缩前把这些内容留在可读笔记中，保留重要证据链接和改变方向的理由；恢复后按需要回读来源，不全库重扫或重审已收录材料。
材料续跑按委派参考处理，仍在运行或结果不明的 writer 不另派。

## 输出

以研究发现、认识如何发展及尚存疑问为主，链接札记、综合和关键材料，让用户看见哪些材料或笔记引出了哪些后续探索，说明下一步或本次停止原因。
材料数量与处理状态作为补充，区分已收录、只有来源链接和待处理的材料。单件收录或 draft 请求则报告对应结果。
