# 按批次滚雪球找文献

如果你是被直接派到这里的，先读本技能根目录的 `SKILL.md` 和 `research/README.md`。

用户要从一批文献出发，沿参考文献一批批扩展时，走这条路。它复用现有的检索、收录、阅读、验收和 Rex 派工，不是另一套收录工具。

核心顺序是：**确定本批材料 → 完整处理本批 → 汇总本批参考文献 → 去重、判断相关性并排序 → 取前十件为下一批 → 重复。** 不要边搜索边无限追加正在处理的批次，也不要让检索会话脱离已读材料，自己不断发散。

## 开始：拿到第一批

先明确研究问题和范围，读已有 Topic 和本地相关积累。

- 用户给了种子文献，就以它们作为第一批，不必先搜一大堆替代它们。
- 没有种子，就用 `quasi search paper`、`quasi search book` 等现有检索能力，按问题的关键词找一批候选。核对题名、作者、年份和摘要，选出第一批，默认十件。
- 已在文库中完整处理过的种子直接复用，回读笔记和原文，不重复下载或写作；缺的步骤按收录流程补齐。

把研究问题、种子来源、本批名单和批次号记在研究工作区的一份 Markdown 记录中。沿用用户指定的项目位置；没有指定就放在该 Topic 的 `processing/` 工作区，不往 Topic 正式页面里塞派工记录。每轮继续更新这份记录，不另造数据库或状态系统。

## 一、完整处理这一批

本批名单定下来后，按 `collect/README.md` 把每件材料交给对应的材料会话，派工使用 `connectors/rex.md`。每件一名材料工人，从身份核验、获取全文、提取到阅读笔记和验收，走完该类型的现有流程；写作仍由材料会话另派写手。并发数量和权限沿用连接器及用户设置，给下级写手留出 pane，不把十件一次全开。

派工时除了材料线索、Topic 和收录入口，再交代：**处理完材料后，通读全文的参考文献、尾注和脚注，把其中可能与研究问题相关的文献提出来，并注明它在原文中的位置和用途。** 为每件材料指定各自的线索文件，避免多人写同一个文件。线索里要有：

- 原文给出的书目信息；能确认的 DOI 或链接。
- 来自哪件材料、哪一条参考文献或哪章哪注；不把搜索结果里的相似题名冒充这条引用。
- 为什么可能相关，以及原作者在哪里、为了什么引用它。仅凭题名的判断要说清楚。

先扫完该材料的整份参考目录及有关注释，再挑可能相关的，不能只读笔记里恰好出现的几条。书的引用可能散落在各章尾注，不能只看精选书目。保留原始书目文本的位置，后面核身份或排序有疑问时能回查。

主会话等待这一批逐件得到明确结果。等待不是派完就停：执行期间主动轮巡材料会话、下级写手与实际产物，发现审批、失败、空转或已交付等待时及时接手；完成一件就独立验收并推进同一固定批次的后续材料，不等用户催。长命令还在正常运行时不反复打断，也不为保持忙碌而追加下一批。暂停或结束主会话时，明确哪些工人仍在运行、停在哪里；没有持续执行就不能声称仍在后台监工。

完成项回到磁盘，用 `quasi status` 和 `quasi audit` 验收；再读阅读笔记和提取的参考文献，必要时核原文。全文拿不到、提取失败或笔记返修仍失败的，单列缺口，不当成已经读完。已经拿到可靠参考目录但没有正文的，可以提线索，不过必须标明依据只是书目。

**这一批全部完成或明确记为阻塞后，才选下一批。** 个别阻塞不无限拖住整轮；保留原因和重试条件后继续。不要只等第一篇完成，就从它的参考文献里抢先选下一轮十篇。

## 二、合并参考文献，选下一批

汇总本批所有材料提出的候选，回查各件的参考目录有没有漏掉明显相关的文献，再做统一去重和身份核验。

先按 DOI、书籍版本、题名与作者合并同一文献，区分预印本和正式发表稿、书及其章节，保留所有发现出处。与之前各轮的已处理、待处理和阻塞项对照：已处理项不再占新一轮名额；阻塞项单列，除非有新的获取线索，不在每轮重复派。

对尚未处理的候选，用现有检索能力补齐书目信息、摘要或目录。身份不明的先保留为待核，不为了凑十件就把猜测的题名派出去。

排序由主会话统一做，不让每个工人各选十篇直接开下一轮。主要考虑：

- 与研究问题的直接关联，预计能回答什么。
- 能补上什么尚未覆盖的解释、时期、地区、技术或实践，而不只是重复本批结论。
- 本批作者为何引用它：核心论据、争论对象、重要综述，还是顺带提到的背景。
- 在不同材料中被反复引到的情况；引用多只是线索，不自动等于重要或相关。

不必造数字评分公式。给出一个有次序的候选表，每项简短说明入选理由和证据依据，明确区分全文、摘要和书目层面的判断。不要因为暂时难下载就把重要文献排掉，也不要因为容易拿到全文就挤掉更相关的材料。

取前十件作为下一批；不足十件就取实际数量，不凑数。其余候选留在累计候选池，后面每轮与新候选一起重新排序，避免旧线索被遗忘。主会话可以继续扩充累计目录，但不能越过本轮排序，随意把搜索到的文章塞给材料工人。

默认沿参考文献向后追。用户另要前向引文、同作者作品或关键词补检时，把它们作为明确标注来源的补充候选，与参考文献候选一起排序，不让补检取代这条批次主线。

## 三、进入下一轮，保留研究进展

下一批仍按同样的完整收录流程处理，结束后再提参考文献、合并、排序、取十件。每轮记录本批实际收了什么、复用了什么、哪些阻塞、候选来自哪里、下一批选了什么及理由。不要把候选数、下载数和完成阅读数混在一起报告。

读完本批后，按 `research/README.md` 更新研究地图，交写手更新资源页。综述等到有实质认识推进再写，不必每批重写；保留用户内容。研究页反映证据和认识，批次记录负责续跑，两者不要混用。

轮数沿用用户要求；没有指定时，默认完成两批处理与各自的候选整理后报告，列出已选好的下一批，而不是擅自无休止开工。可核实且相关的新候选已经不足、连续批次主要回到已有材料，或资源限制使下一批无法开展时，说明情况，由用户决定是否扩大范围或换关键词；不能仅因为名单很长就声称已经穷尽。

续跑先读批次记录，核对材料的实际产物，补齐中断步骤，再从尚未完成的本批继续。不要重开一轮漫无目的的搜索。
