# PDF extraction and translation pipeline

Measured institutional memory for `scripts/extract/` and `scripts/translate/`.
Every constraint below was a real regression or a measured trade-off; the
numbers were paid for on real books. The enforceable digest lives in
`CLAUDE.md` under "Extraction and translation invariants"; this file holds the
full reasoning. Do not relax a rule here without rereading its paragraph.

## Translation backends

`quasi-translate` has two interchangeable backends behind one output contract (`processing/translations/{slug}-{canonical-target-lower}.pdf`; Mainland Chinese is canonical `zh` and therefore uses `-zh.pdf`; alternating original/translated pages, bookmarks): `immersive` (default, Immersive Translate Zotero API) and `pdf2zh` (local `pdf2zh-next` via uvx, driving a user-supplied OpenAI-compatible endpoint). Backend selection is user config (`translate_backend`), not a free caller argument. `translate-agent` owns the Translation Prepare Stage: it observes candidates, runs the configured backend, interprets validation, and requires paragraph layout OCR before translating image-bearing source pages. The deterministic CLI still owns fenced generation, manifest-last publication, page-count, ToUnicode, and coverage checks. Provider adapters map canonical `zh` back to `zh-CN`; other canonical target tags remain distinct. For pdf2zh, a root-only `translate_base_url` gets `/v1` appended; any explicit path is preserved because compatible providers also use paths such as `/api/paas/v4` and `/openai/v1`. The pdf2zh path uses `--use-alternating-pages-dual`, which emits the same page layout Immersive produces *after* `split_dual_pdf()`, so the TOC helpers are shared verbatim. Provider credentials stay out of argv. Rejected or uncertain generations remain in their fenced `processing/translations/.{stem}.translate-*` directory and never become canonical output.

## Required layout preparation and successful cleanup

Before starting either provider on a new generation, `quasi-translate observe|run` checks for page image objects using the same predicate as `relayer_page`. Image-bearing sources without verified layout evidence return `translation.layout_required` before task creation. Fonts are irrelevant: the ABBYY Archer scan uses TimesNewRomanPSMT. The specialist prepares the request's existing recovery path (`processing/translations/{slug}-zh-reocr.pdf` for Chinese), observes that exact source, and translates it. Pages without image objects keep their original text; an entirely born-digital PDF needs no OCR. Existing coherent committed translations remain reusable.

Successful layout output embeds `QuasiLayout` evidence (`quasi.ocr.layout/0.2`, profile `mineru25-pro-2605-layout/1`) in the PDF catalog, including the input SHA-256, page/image-page counts, actual grouped-page/paragraph counts and an extracted-text digest. No sidecar or new recovery path is added. `--no-clobber` only reuses layout output if the evidence matches the current input and text; legacy, modified or unrelated recovery PDFs stay untouched and fail validation. This is local provenance and quality evidence, not a cryptographic signature. The CLI rejects a raw scan even if it was renamed to the recovery path.

Layout mode requires MinerU recognition and paragraph placement. Model/import failures, malformed or incomplete page results, empty recognized text blocks, or any paragraph that cannot fit fail before publication. There is no per-line or automatic Tesseract fallback. A whole image-bearing document with zero placed paragraphs also fails. Blank/image-only pages can legitimately have no recognized text; their source images remain available for inspection. Tesseract remains an explicit non-layout choice only. Old DS OCR2 layout evidence cannot authorize a new translation generation; already committed coherent translations remain reusable.

A committed translation recursively removes only its successful work directory, including pdf2zh's nested caches. Failed or unknown generations remain inspectable. A later strict run that reconciles the same committed request also removes matching `published` work directories left by an interrupted cleanup. The temporary lock pathname is removed while held; every waiter checks its inode after acquiring the lock and reopens a detached inode before entering the transaction. Unlinking without that check would allow two writers on different lock inodes.

## Long-running translation supervision

A whole-book translation can take more than an hour. `translate-agent` waits in separate Bash observations of at most 60 seconds, but that is a per-observation bound, not a total monitoring budget. It continues observing the same identifiable writer through completion rather than returning `blocked` after 30 minutes or a fixed number of checks. Each observation keeps only new progress or a compact status; missing output or a temporarily unchanged log does not establish failure. Actual uncertainty about writer ownership/outcome still stops writes. A host-enforced end to the invocation must retain the exact PID, log/receipt paths, last observed progress and stop reason for reconciliation; a subsequent dispatch observes the existing writer before considering another write.

Immersive's adapter formerly had a separate 180-check limit at 10-second intervals, so it could time out a responsive remote job after about 30 minutes. By default it now polls the same task ID until terminal success/failure, transport failure or interruption, and emits progress plus a heartbeat at least once per minute of responsive polling to stderr. An explicitly supplied `max_polls` remains supported for bounded callers. This changes neither task creation nor publication: one paid POST, one fenced generation, and the same page-count/ToUnicode/coverage checks before the manifest-last commit. The local pdf2zh subprocess already has no total runtime timeout.

## Coverage gate

Both backends gate on translation coverage (`scripts/translate/coverage.py`), because a structurally perfect dual PDF — right page count, exit 0, no warning — can still omit much of its body text. Fragmented source text can prevent BabelDOC from recognizing translatable paragraphs. The Chinese body gate requires a per-page median of at least **0.30** translated Han characters per source Latin letter. The previous 0.22 threshold admitted a visibly incomplete translation at 0.23. Pages with a ratio **below 0.05** may account for **at most 10%** of the measured body pages; more than 10% fails, while exactly 10% passes. These are quality thresholds, not a literal percentage of content translated.

Reference material needs a different measurement scope, not a lower blanket threshold. On 2026-09-26, BTS's Greenspan dual PDF scored median 0.30087 but had 58/279 near-zero pages, largely bibliography and chapter notes left in English. Its current Buthe–Mattli candidate scored 0.29389 across 304 pages including references/index; before the References section its median was 0.30014. The ratio alone cannot distinguish reference material from omitted prose.

The checker therefore uses source structure, independently of target ratios:

- Exact outline labels such as Bibliography, References, Works Cited, Index, Notes and Endnotes identify reference sections through the next sibling/ancestor entry (or document end). Descendant entries remain in that section. Substring matches such as “Notes on Method” do not qualify. Outline destinations on either side of the alternating PDF map back to physical source-book pages. If at least 200 Latin letters precede the matching heading, retain that mixed opening page. Source blocks are sorted by position because OCR content-stream order can put the heading after the entries. Missing, invalid or out-of-order outlines yield no exemptions.
- An unbookmarked, standalone Notes/Endnotes heading followed by numbered entries 1 and 2 can identify chapter-note continuation pages, but only inside an outline section with a later bookmark to bound the range. Keep its opening page, which can mix body and notes; stop before the next bookmark, even a subsection. Without a known boundary, keep scoring the pages. Mixed footnotes, quotations and acronyms in ordinary body pages are not automatically exempted.
- Both median and near-zero numerator/denominator use the same remaining pages with at least 200 source Latin letters. Low-text plates and title pages remain unmeasured. If exemptions would leave fewer than three measurable body pages, use the unfiltered set rather than turning a measurable failure into an insufficient-evidence pass. A document that originally has fewer than three measurable pages still reports insufficient evidence.

Reports retain excluded ranges and their evidence, excluded/measurable counts, unfiltered median, thresholds and weakest physical source-book pages in `detail`, including the existing persisted receipt/manifest shape. Passing proves the body gate only: excluded references and notes are **not translation-validated**. Unsupported or ambiguous sections remain measurable and can still cause a false rejection; low coverage is evidence to inspect, not proof of damaged OCR. No semantic page classifier or book-specific relaxed threshold is used.

Read-only remeasurement with these rules gives Greenspan **0.31038 over 204 pages, 0 near-zero**, excluding 75 measurable reference pages, and Buthe–Mattli **0.30014 over 250 pages, 0 near-zero**, excluding 54. Both pass without lowering 0.30 or the 10% policy. BTS's retained older Buthe–Mattli PDF still fails at **0.29165 over 258 pages**, with 9 near-zero pages. This is a measurement regression check plus selected-page visual inspection, not a full translation-quality audit; the PDFs were not repaired, translated again or published during the check. File hashes and exclusion evidence are recorded in [the measurement record](evals/translation-coverage-sections-20260926.json).

Only Chinese targets are scored. The check must run *after* `tounicode.py::repair_pdf`, and does in both backends: an unrepaired book extracts as mojibake in the CJK extension-A block, which the counter deliberately does not count, so a healthy 368-page translation scored 0.17 before repair and 0.31 after. Repair old PDFs before standalone auditing. `translate-agent` interprets the scope and weak-page evidence inside Prepare before choosing recovery; the skill sees only the final Stage terminal and verified generation.

## ToUnicode repair

Both backends run `scripts/translate/tounicode.py::repair_pdf` on the finished PDF. BabelDOC — which Immersive Translate's PDF pipeline also uses, same font stack — emits a `/ToUnicode` CMap holding a couple of dozen entries instead of one per glyph once a run exceeds a few translated pages. The pages render correctly but copy/paste and in-PDF search return mojibake, because the reader falls back to reading the raw CID as a codepoint. The subset fonts are Identity-H with original glyph numbering, so the map is rebuilt from the cached original TTF under `~/.cache/babeldoc/fonts` (override with `QUASI_BABELDOC_FONT_DIR`); every rebuild is cross-checked against the entries BabelDOC got right and a font that disagrees is skipped rather than corrupted. Run the script standalone to repair PDFs translated before this existed.

## OCR engine: MinerU2.5-Pro

`quasi-extract ocr` defaults to direct **MinerU2.5-Pro** recognition: `MinerUClient(backend="mlx-engine", model_path="opendatalab/MinerU2.5-Pro-2605-1.2B").two_step_extract(image)`. One uvx subprocess loads the model once, then processes the invocation's pages rendered at 200 dpi. It pins **mineru-vl-utils==2.0.5, mlx-vlm==0.7.3, mlx==0.32.2**, with Pillow, torch and torchvision in that isolated environment. The previous mlx-vlm 0.3.12 pin cannot call `two_step_extract` (`should_add_special_tokens` import failure); the old `mlx<0.32` constraint belongs only to the retired implementation. Model selection is fixed and part of the generation profile. Apple Silicon and uvx are required; failures propagate. `--engine tesseract` / `--profile tesseract-text` remain explicit non-layout alternatives.

The 2026-09-26 proposal replaced DS OCR2 after measured missing lines (Harrington p31), glued words, damaged table translation, and missing Chinese footnotes. MinerU supplies recognition and paragraph geometry together, eliminating the independent DS recognizer and layout-only grouping call. Ordinary OCR preserves the model's block reading order, drops running furniture, keeps notes separate, and retains table/formula text. It does not undo hyphens a second time after paragraph recognition. Text overflow, missing Unicode fonts, unknown block types, invalid boxes and unsupported LaTeX commands fail rather than silently discard recognized content. `pylatexenc==2.10` converts supported inline mathematics, and HTML table cells remain separated in ordinary extraction.

## Source-bound OCR generations

Paper and Book share `quasi-extract ocr-generation`. The owned roots remain `processing/papers/{slug}/` and `processing/chapters/{slug}/`. Generation keys bind the accepted PDF path and SHA-256 to the closed profile, including MinerU's model and implementation revision. Private ranges live under `.ocr-work/{generation-key}/`; immutable results live under `ocr-generations/{generation-key}/{ocr.pdf,ocr.txt,manifest.json}`. Each foreground invocation advances at most one missing contiguous range before returning for a fresh status observation. `mineru-text` owns 16-page ranges; explicit `tesseract-text` owns 32-page ranges. Neither silently changes engines.

Publication is manifest-last and no-clobber. Existing ranges must match exact paths, source generation, engine, bounds, SHA-256, page count and PDF quality; MinerU also requires valid embedded quality evidence. An orphan MinerU range is compared with the exact deterministically sliced source before recovery, without rerunning a writer. Final page counts must match. Paper requires measurable text on every page; Book allows structurally valid blank scan pages. Normalized text binds to the recovery PDF hash. Source/profile drift selects a new generation key; unknown inventories stop without replay.

The old `dsocr2-text` profile retains its original fingerprint and manifest schema for read/reconciliation only. Committed generations are reusable through their exact old profile; partial DS generations cannot advance with MinerU. Historical fixed Paper artifacts remain untouched. The fixed eight-page Book capability remains available for existing compatible progress, but DS progress requires a fresh MinerU generation instead of mixed-engine continuation. New work never creates fixed legacy progress. Translation layout remains a single foreground operation because dominant-size evidence is book-wide.

## MinerU layout and evidence

Layout keeps the scan image and strips old text including Form XObjects, then places one invisible textbox per recognized paragraph **over** the image. Born-digital pages with no image objects retain their original content. Font names do not classify scans. Base-14 Helvetica is used where it covers the text; other characters require a font that covers every recognized codepoint and are never dropped to force a fit. Existence of a Unicode font is insufficient: Arial Unicode lacks Romanian `ș`, found in Barnes p69 (Ceaușescu). Check glyph coverage and an actual write/extract round trip, select another available font with a distinct PDF resource name, or fail explicitly. Arial/Times fallback fonts can contain `ș` yet map hyphens/semicolons to other codepoints in their PDF ToUnicode tables; Georgia passed the same round-trip check.

MinerU's normalized paragraph boxes replace DS OCR2's grounded line boxes. The font size is the largest that fits the complete paragraph at line height **1.15**. Long body `text` blocks establish the book-wide median; body sizes within **±20%** snap to it. Titles, running heads, page numbers, marginal text, captions and notes keep their own fitted sizes. Placement starts at **0.90** of the fitted/snapped size and tries 0.85, 0.80 and 0.75 only if needed. A paragraph that still cannot fit stops publication. There is no per-line placement path.

`text`, `title`, `paragraph_title`, `ref_text`, `page_footnote`, `table_footnote`, and captions are independent textboxes. All three footnote labels matter because the model uses them inconsistently. Furniture keeps its own size. Empty `list` containers add no text; their recognized children carry the notes. `table`, `equation`, and image blocks add **no layout text**, so BabelDOC cannot shred their original image into translated line fragments. Ordinary OCR still emits recognized table/formula content. Inline math and HTML are cleaned before placement, including superscript note numbers. Rotation follows the model's crop orientation.

In addition to `QuasiLayout`, both OCR outputs carry `QuasiOCR` (`quasi.ocr.evidence/0.1`, profile `mineru25-pro-2605-text/1`) bound to the source hash, model, page count and extracted-text digest. For body paragraphs with at least ten word tokens, compare new word order with the source page's old text layer. Agreement below **0.85** records page, block, box, score and short old/new excerpts. `ref_text`, `page_footnote` and `table_footnote` are exempt. A text block containing at least three page ranges is also exempt when both the old source and MinerU agree on an exact Notes/References/Bibliography heading at the top of the page. Merely containing names, acronyms or a title such as “Notes on Method” is insufficient. Comparison normalizes compound and line-break hyphens alike without changing the emitted recognition text; fewer than 50 old tokens means the baseline is unavailable, not a successful check. Empty model pages are recorded separately in `empty_pages`; an empty page with at least 50 old tokens fails. This distinction is measured: Barnes physical page 176 is visibly blank paper with 44 old OCR noise tokens. With an unavailable baseline, retain the image and record the empty result rather than claiming recognized text. The default keeps new recognition and reports differences. Old text can itself be wrong: the real Harrington p41 sample is a readable new paragraph against garbled old OCR. Agreement is a review signal, not a truth test or an automatic reason to restore old text.

MinerU generation manifests use `quasi.ocr.generation.manifest/0.2` and include combined quality evidence with source-book page numbers. Other profiles retain manifest 0.1. Direct `ocr` writes only its named PDF; its embedded evidence avoids adding an uncontracted sidecar. Suspect text remains inspectable in the result. Books without an old text layer have no independent recognition check.

## Historical measurements before the MinerU replacement

The following paragraphs preserve the original experiments and failure explanations. They describe the retired DS OCR2 implementation, not current commands, dependencies or fallback behavior. Current requirements above supersede their implementation instructions.

### Retired DS OCR2 engine

`quasi-extract ocr` defaults to **DS OCR2** (DeepSeek-OCR-2 via `mlx-vlm`, Apple Silicon). The engine pins **mlx-vlm==0.3.12** — 0.4+ breaks this model's loader ("Unrecognized processing class") and generate path ("TokenizersBackend has no attribute stopping_criteria"); 0.3.12 is the last version that runs DeepSeek-OCR-2 end to end. The cause is *not* transformers: 0.3.12 already requires `transformers>=5.1.0` itself, and the only declared dependency delta to 0.4.0 is `mlx-lm` (0.30.7 vs 0.31.0). Do not reject a candidate model for needing transformers 5.x — that reasoning was wrong once already and it excluded GLM-OCR. Both DS OCR2 and MinerU uvx commands also constrain **mlx<0.32**: MLX 0.32 is incompatible with the pinned mlx-vlm 0.3.12, and previously made every MinerU page fail while the fail-soft wrapper returned success. The constraint belongs in both command lines, so callers no longer need a manual UV_CONSTRAINT workaround. It also pulls torch/torchvision/addict/einops/matplotlib/tqdm (the model's remote-code imports), all via uvx — NOT in `requirements.txt`. Ordinary non-layout OCR auto-falls-back to tesseract if uvx, the model (`QUASI_DSOCR2_MODEL`, a local BF16 dir or HF repo id), or Apple Silicon is missing; `--engine tesseract` forces tesseract. The DS OCR2 path writes a text-layer PDF (one page per input page) so the existing `split` flow is unchanged.

Never pass `trust_remote_code=True` when loading this model: mlx-vlm ships its own `DeepseekOCR2Processor`, while the HF repo's remote code imports `LlamaFlashAttention2`, deleted from modern transformers. mlx-vlm swallows that ImportError in `models/base.py` and re-raises it as a bogus "Unrecognized processing class", which sent every run silently down the tesseract fallback. `tests/test_extract_cli.py` guards it.

### Retired grounded-line replacement

`--layout` switches the output shape: instead of reflowed markdown it writes the source's own pages with their text layer replaced — scan image untouched, invisible text at the boxes DS OCR2 returns for the `<|grounding|>` prompt (a 0-999 space, normalised to the page). This exists to feed `quasi-translate`: BabelDOC carries the *source* font size onto the translation (measured at a constant 0.90x across both of a slice's two source sizes, character counts in the same ratio), so whatever size the OCR layer writes is what the Chinese renders at. Three constraints are load-bearing. The text is drawn *over* the image, not under it the way ocrmypdf does — BabelDOC substitutes the translation in place, so an ocrmypdf-shaped source yields a translated page that extracts fine and renders as the untouched English scan. The font is base-14 Helvetica whenever it covers the text: PyMuPDF embeds a fontfile whole and cannot subset without fontTools, so an unconditional Arial Unicode adds ~16MB per output. And every line's size is snapped to the book's dominant one (`dominant_size` / `SNAP`, character-weighted median over every grounded line, book-wide because one page holds too few lines to see through the noise): a box hugs its ink, so its height tracks whether the line has ascenders rather than its type size, and identically-set body lines otherwise compute -9%/+4% apart — which is precisely the "字号时大时小" symptom, 25 distinct sizes on a slice whose source layer used 2. Snapping puts 99.6% of characters on one size. It also flattens headings and no threshold avoids that: the same slice's chapter title is set 1.36x body in the source but its *box* computes to 1.12x where body lines already reach 1.07x. Fixing that needs an engine that labels blocks rather than lines: `mlx-community/dots.ocr-4bit` returns `{bbox, category: Title|Text|Section-header, text}` per paragraph, runs on the same mlx-vlm 0.3.12 pin at 6-8s/page against this engine's ~20s, and over the same 10 pages made 1 word error against DS OCR2's 6 plus 2 silently dropped phrases — its one real loss is that it eats superscript footnote markers. Its boxes are in the input PNG's own pixel space, not a 0-999 grid. Surveyed and left unwired. Stripping the old text layer must reach **Form XObjects**, not just `page.get_contents()`: ABBYY-style scans park their OCR text in a Form named `OCR-<id>`, and five of eight books measured are that shape. Missing it left two stacked text layers, which BabelDOC answers by silently dropping body text — coverage 0.23–0.29 against a healthy 0.33, one book losing its longest paragraph on every page. Only `/Form` subtypes are rewritten; the same `BT…ET` regex over an image stream would corrupt it. A page with no image object is skipped entirely (`relayer_page` returns -1): it is born-digital, its text *is* the page, so stripping would blank it — and the layer it already has is the clean one `--layout` exists to reconstruct for scans. Note that a scan can still carry real font names; `archer-culture-and-agency-1996.pdf` is an ABBYY-style scan whose text layer uses TimesNewRomanPSMT, not tesseract's `GlyphLessFont`, so the image object is the reliable test, not the font name.

### Retired DS OCR2 + MinerU grouping

`--layout` writes one flowed textbox per **paragraph**, not per line, and that is the single biggest readability win in the translation path. Handed a line box, BabelDOC must fit that line's Chinese into that line's width and parks the tail in the margin, so a paragraph arrives cut into pieces — measured on three books' 10-page slices, per-line produced 11/12/19 margin scraps and 20/34/77 overlaps, paragraph flow 1/3/33 and 0/7/32, and it fixed the coherence on 3/3. A paragraph box has nowhere to spill: it rewraps internally. The grouping comes from **MinerU2.5-Pro** (`opendatalab/MinerU2.5-Pro-2605-1.2B`, `QUASI_MINERU_MODEL`) called through `MinerUClient.layout_detect`, which returns `{type, bbox}` and **no text at all** — DS OCR2 keeps every bit of its recognition advantage and MinerU is used purely as a grouper. Same mlx-vlm 0.3.12 pin, ~2s/page against DS OCR2's ~20s. Explicit layout now requires MinerU: all-page failure is an error, including exit 0 with empty blocks or a run where no grouped paragraph was actually placed. Partial unclaimed text still uses measured per-line placement. Leading comes from the source's own line pitch, so the flow lands on the ink it replaces instead of needing the box to grow — growing is what makes boxes overlap and translations stack. Five things are load-bearing. Geometry (nesting, bottom-edge extension) runs over **every** block and the flowable-category filter comes **last**: filter first and a `list` of footnotes looks childless once its `ref_text` children are gone, so six numbered notes flow as one blob, and a body block above a figure grows through it and swallows the caption — both were real regressions on book two. `FLOW` includes `ref_text`, because a footnote is a paragraph and leaving it per-line reproduces exactly the shredding this path exists to fix; it was the largest flowable category being dropped (44/52/52 lines on the three footnote-heavy books of eight measured) and adding it took margin scraps 3→1 on galison and 32→15 on hounshell. A block's box comes from **sorted** line extents, never from `lines[0]`/`lines[-1]`: grounding order is reading order, and on a page with figures a block's last line can sit above its first, which built an inverted rect and crashed PyMuPDF outright. Lines no block claims stay per-line, and furniture outside every block keeps its measured size rather than being snapped to body, because snapping made BabelDOC read a running head as the first line of the paragraph under it. The source layer is written at a flat `SHRINK` 0.90: BabelDOC sets CJK at `line_skip` 1.50 (`typesetting.py`) into a box a scanned book built at ~1.15 pitch, and that vertical deficit — not character width, since Chinese needs only 0.70x the width of English at the same size — is what overflows; below scale 0.70 BabelDOC stops shrinking and expands the paragraph box rightwards instead, which *is* the margin scrap. And the shrink is flat rather than per-paragraph because BabelDOC caps every paragraph at `min(multimode(scales))` document-wide, so a mixed source comes out mixed (41-49% of characters on the dominant size against 72-94% for a flat one); 0.90 measured identical to 0.85 in defects on three books, 0.95 gained nothing on the densest of them and halved its uniformity, and 1.00 collides. The constant is deliberately not calibrated per book: across five further books, 0.95 and 0.90 produced the same margin-scrap counts to within noise (9/9, 23/23, 0/0, 7/7, 12/12), so the per-book variance that looked like a density problem was three bugs, not a missing knob. Block lines are joined with `join_lines`, which undoes end-of-line hyphenation (104 cases over two slices) at the join rather than on the joined string, so the real hyphen in `pre-logical` survives.
