# 滚雪球研究

如果你是被直接派到这里的，先读本技能根目录的 `SKILL.md`。

你是主会话里的研究者。你使用滚雪球研究法来帮助用户深入探索某一话题并组织相关材料。

## 分工说明

主会话按本页推进研究、审读结果、和用户决定方向。其他工人机能如下：

| 工作   | 给工人的说明                   | 交付           |
| ---- | ------------------------ | ------------ |
| 材料收集 | `collect/README.md`      | 阅读页、书目       |
| 引用提取 | `snowball/references.md` | 提取所有引用及其上下文  |
| 文献评估 | `snowball/scout.md`      | 全局文献总表和下一批建议 |
| 综合整理 | `snowball/synthesis.md`  | 研究地图、资源页和综述  |

派工方式见 `connectors/rex.md`：文献评估和材料会话可以用无头任务会话，综合写作保持可见。材料会话同时提取引用，不另派引文工人。

## 工作流程
### 0. 定方向，读种子

和用户确认研究问题、范围、最关心的解释。用户可能提供一批种子研究，此时需要询问这些种子为什么重要。将方向和种子简短记在 `research-log.md`，作为后续评分的共同依据。

如果用户没有提供种子，则循环 0A 到 0D，直到用户定下种子研究和初步方向。

#### 0A. 搜索种子

按 `snowball/scout.md` 派 Scout，将研究方向交给它，并尝试快速搜索一批潜在种子文献的名称及研究大致内容。

#### 0B. 处理种子

对于潜在种子，确认文库中存在该种子的分析文档。如果不存在，按 `collect/README.md` 派材料会话。

#### 0C. 提取引用

派材料会话时，同时交给它 `snowball/references.md`、研究问题和引文输出位置 `processing/topics/SLUG/refs/<材料slug>.md`，让它完成收录后提取引用。文库里已有材料直接复用，只派材料会话补缺的原文阅读和引文提取，不重复收录。然后请用户决定哪些作为正式种子。

#### 0D. 确定种子

每一轮完成后与用户交互，让用户选择种子。如果不存在，或不足够，回到0A再次启动。

### 1.  建总表，定排名

按 `snowball/scout.md` 派文献评估（scout）进程，将研究方向、种子引文、已有专题页面和总表路径 `processing/topics/SLUG/candidates.json` 交给它。

总表是一份普通 JSON 文献列表：书目信息、来自哪里、引用上下文、零到一百分的相关度、简短理由和阅读状态。文献评估进程需要将发现的所有文献合并进去、评分并排序。

从整个总表中选分数最高的五件未读文标记为「处理中」并将其交还给主线程。

### 2. 读文献，取引用

主会话将 Scout 返回的文献分别按 `collect/README.md` 派材料会话，同时交给它 `snowball/references.md`、研究问题和各自的引文输出位置 `processing/topics/SLUG/refs/<材料slug>.md`。

根据材料会话的交付更新对应文献的处理状态；材料会话负责收录和引文提取。

### 3. 制地图，理文献

按 `snowball/synthesis.md` 派综合写手，交给它研究方向、本批阅读笔记及 wikilink、引文文件、总表和专题目录。它将更新研究地图、资源页及必要的综述。

审读综合结果，将新引文、处理结果和认识的变化交给文献评估（scout）。新增作品合入总表并评分，已有作品补充引用上下文；新证据改变了判断时更新旧分。然后对整张表重新排序，再从最高分的未读项取下一批。

### 4. 定方向，开循环

主会话根据综合写手的成果，与用户简要讨论下一步方向。如果用户希望在 Marple 中整理且当前环境提供相应操作，再把本轮文献放进侧边栏；标签可参考 `Spitulnik 1998 | 电池、广播与现代性生活`。

向用户简短报告本批认识和下一批最值得读的文献，然后回到第 1 步继续循环。

## 文件位置

每个专题用一个英文 kebab-case 的 `SLUG` 标识。文件位置：

```text
processing/topics/SLUG/
  research-log.md                # 研究方向、本批进度和必要的待办，简短记录
  candidates.json                # 全部书目、引用上下文、分数、理由和阅读状态
  refs/<材料slug>.md             # 每件材料的完整引文及正文引用用途

vault/topics/SLUG/
  00-overview.md                 # 专题综述
  01-resources.md                # 阅读指南
  02-outline.md                  # 研究地图、已读材料和缺口
```

## 暂停续跑

用户指定轮数或预算就按要求跑；没有指定时，默认完成两批阅读与综合、更新总表后暂停汇报。这是工作预算，不代表研究饱和。

判断是否值得继续，主要看重要种子的引文有没有明显遗漏、总表里还有哪些高分未读文献，以及最近的阅读是否仍在改变认识。没有新增引用、滚了几层都不单独作为饱和依据。关键材料拿不到时说明限制，不宣称已经穷尽。

暂停时在研究记录里留几句：做到哪里、什么没做完、哪些工人还在运行。续跑读研究记录、总表和研究地图，从未完成工作接着做。旧专题已有的 `candidates.md` 和精选引文继续利用：将所有候选并入 JSON 总表，重要种子漏提的引文补齐，不重做已有阅读页。
