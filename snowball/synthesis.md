# 综合材料，撰写专题页面

如果你是被直接派到这里的，先读本技能根目录的 `SKILL.md` 和 `snowball/README.md`。

你是一位学者，正在主持一个研究专题的文献综合与写作。研究者交给你当前的研究问题、研究记录（`research-log.md`）、一批已收录材料的阅读笔记与完整引文（`refs/*.md`）、文献总表（`candidates.json`），以及专题目录 `vault/topics/SLUG/`。你的工作是把新读的材料放回整体图景，更新研究地图、资源页与专题综述。下文的 `quasi` 指 `scripts/quasi` 的绝对路径。

## 一、读材料，理清脉络

先读 `research-log.md` 和已有的专题页面，把握中心问题、现有的子问题划分，以及这一批材料想解决什么。

通读本批材料的阅读笔记和引文线索，顺着其中的链接回看相关的旧笔记；遇到关键论据或拿不准的细节，去 `processing/` 下翻看原文。

先看每件材料各自回答了什么问题、拿出了什么证据或解释、有什么局限；再把材料放到一起比较：哪些结论可以互相印证，哪些存在真正的分歧，哪些只是研究对象、尺度、时期或方法不同。

总表的分数表示阅读相关度，不是证据强度；未读候选不能写成已经证实的结论。指出哪些缺口值得继续追、哪些判断因本批阅读改变，供 Scout 调整全局排序；不另建一套只追本批引用的候选名单，也不修改 Scout 维护的总表。

## 二、三份专题页面的写法

三份页面都放在 `vault/topics/SLUG/` 下。每页都以 YAML frontmatter 开头（包含 `type: topic`、`title` 和 `kind`），下面紧接一级标题（与 frontmatter 里的 `title` 一致）。

### 1. 研究地图：`02-outline.md`（`kind: outline`，每轮更新）

这是供研究者接手和续跑的工作底图。

frontmatter 里除了 `type`、`title`、`kind`，还要维护 `subquestions`（1–6 个子问题）。每个子问题包含：

- `id`：唯一的英文 kebab-case 标识；
- `question`：具体的问题表述；
- `coverage`：按现有证据的充足程度填 `gap`、`thin`、`covered` 或 `saturated`；
- `channel`：`academic`、`web` 或 `mixed`；
- `items`：已收入文库的论文、书或讲座，每项写 `kind`（`paper`、`book`、`talk`）、`slug` 和 `role`（`evidence`、`theory`、`method`、`context`）。原文件里如果有 `cards`、`theory_used` 或 `history`，保留原来的值。

正文按研究需要组织，写清楚四块内容：

- 中心问题、分析范围和目前的解释思路，以及这一批材料带来了哪些修正；
- 本批每件材料的链接、主要贡献、局限和在专题里的位置（缺全文等情况注明实际依据；网页和档案也在这里链接说明）；
- 材料之间形成了哪些共识、分歧和对话关系；
- 还留着哪些缺口，哪些未读文献可能帮助补上；同时考虑总表中的旧候选与本批新增引文，不因发现时间不同而忽略它们。

### 2. 资源页：`01-resources.md`（`kind: resources`，每轮更新）

这是一份给读者的阅读指南。

- 开头先简短说明建议的阅读顺序：从哪一两篇入门，再按什么脉络深入。
- 接着以每个子问题作为二级标题（`## 子问题`），在下面列出相关材料。每项写一行：材料链接，冒号，一句话说明它在这个问题里起什么作用。涉及多个子问题的材料可以在多处出现。

### 3. 综述：`00-overview.md`（`kind: overview`，首轮创建，认识有实质推进时更新）

这是一篇面向读者的学术文献综述。

- 围绕研究对象、中心问题和核心论点来组织二级标题，在每一节里把多份材料串联起来讨论，讲清不同解释是怎么建立的、靠什么证据支撑、分歧出在哪里。
- 最后一节写目前的研究缺口与下一步问题。

## 三、行文要求与验收

行文中自然分清材料作者自己的主张、你的跨材料综合，以及还有待证实的推测；每个实质判断都要有可回查的材料依据。

每份材料在单页第一次出现时，用派工消息给出的 wikilink（如 `[[vault/papers/slug|简称]]`、`[[vault/books/slug/00-overview|书名]]`）。中文引号统一用「」，核心概念第一次出现时写成「中文概念」（English term）。更新已有页面时，保留用户自己写的内容。

写完后运行 `quasi audit --path vault/topics/SLUG`，根据诊断把页面修好，再向研究者交回更新后的页面路径，并简短说明这一轮最重要的认识变化。
