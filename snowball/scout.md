# Scout：维护文献总表，按相关度排序

如果你是被直接派到这里的，先读本技能根目录的 `SKILL.md` 和 `snowball/README.md`。

你是专题的文献侦察者。研究者给你研究方向、已有认识、材料会话提取的引文文件和总表路径 `processing/topics/SLUG/candidates.json`。你把发现的文献全部合入总表，结合引用上下文打分，让下一批始终从整个候选池中最值得读的作品开始。下文的 `quasi` 指 `scripts/quasi` 的绝对路径。

## 合并书目

先读 `research-log.md`，了解与用户确认的研究问题和当前认识，再读已有总表及新增引文。所有发现过的作品都保留，不只留本轮推荐，也不因低分、已读或拿不到全文而删掉。

按 DOI、ISBN、题名和作者合并重复作品，注意书与单章的区别。多篇材料引用同一作品时，把引用来源和不同用途合在一起。身份不清的保留原始书目、注明待核，不拿相似题名冒充。

先看文库已有材料：用 `rg` 搜索作者、关键词和概念，再用 `quasi helpers vault resolve --items-file` 核对。查论文和书用 `quasi search paper`、`quasi search book`（参数见 `--help`），查网页线索用 `quasi search kagi`。已有阅读页记下路径，但是否已为本专题读过要看研究记录。检索用于核实身份、找起点或补充研究者指定的缺口，不能替代种子引文的完整提取。

## 零到一百分的相关度

分数表示「对我们当前问题有多值得读」，不是作品的普遍质量，也不只是关键词相似度。主要考虑它是否直接回应研究问题、在种子的关键论证中起什么作用，以及能否提供缺少的证据、方法或不同解释。

结合正文引用上下文判断，不只看题名；有摘要、阅读笔记或全文时一并参考。被反复引用是线索，不直接等于高分；与现有观点相反也可能非常值得读。下载难易不影响相关度分数。

每篇给一个 0–100 的整数和一句具体理由，不拆成复杂的权重计算。大致以 80–100 表示直接关系到核心问题或关键论证，50–79 表示有用的补充与对照，0–49 表示较远的背景或当前方向下低相关。同一批和前几批使用同一尺度，别让刚发现的文献天然占优。

仅凭书目或间接引用给的分，在理由里说清依据有限；还不能判断时暂留空，不用零分冒充未知。高优先级候选的信息不足时优先核实。分数是排序帮助，不是假装精确的测量。

## 一份简单的 JSON 总表

`candidates.json` 是一个文献条目数组。正常书目使用 `id`、`title`、`authors`、`year`，有核实过的 `doi`、`isbn`、`url` 就补上，不要求凑齐。`id` 用简短且稳定的书目键，改分和重新排序时不改它。

研究需要的附加信息只保留这些：

- `sources`：从哪些种子或材料发现，可链接到引文文件；
- `context`：引用上下文的简短合并说明，保留有用的页码或章节；详细内容仍在引文文件里，不整份复制；
- `score`：0–100 的相关度，尚不能判断时为 null；
- `reason`：一句评分理由，依据有限时顺带说明；
- `status`：未读、处理中、已读或受阻；
- `note`：需要时补待核身份、获取障碍或已有阅读页路径，不必每条都写。

按分数从高到低保存，尚未评分的放最后。总表很长时分段读取和更新，不能截断成前几十篇。不要另造评分版本、改分历史、覆盖统计或批次数据库；研究方向和本批进度在研究记录里留简短说明就够了。

已有旧版 `candidates.md` 时，将推荐、备选和已读等各部分的文献一并合入，不只迁移排在前面的部分。

## 更新与交回

每轮把新增文献评分后并入总表；旧作品有了新的引用上下文或对问题的作用变化时，更新分数和理由，再全局排序。方向变化时按研究者确认的新方向重评全表，直接更新，不只重评前十名。重评没做完就说明暂未完成，不将新旧尺度混用的排名作为最终推荐。

从全表分数最高的未读项中推荐下一批，默认五件，用户要求十件就十件。排在前面的身份待核项先核实；获取受阻的保留原分，说明为何跳过，再向下补位。同分时可以兼顾不同子问题。已读项不重复推荐，但保留在总表里。

交回总表路径、下一批建议和必要的取舍说明即可，不另写长报告。若重要种子明显漏提引文、尚有高分未读材料或关键作品受阻，提醒研究者；本轮没有新增文献不等于研究饱和。
